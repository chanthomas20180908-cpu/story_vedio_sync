HappyHorse 视频生成测试复盘

项目：女儿国旧日神事件。目标是验证 DashScope HappyHorse 能否在“天书奇谭式老动画风格”下生成可用于成片的 AI 视频，而不是静态图推进。

记录日期：2026-05-26 测试日期：2026-05-25 模型：happyhorse-1.0-i2v / happyhorse-1.0-r2v 策略：低成本单条测试

阶段结论

有效发现
  • API 链路已跑通：提交任务、轮询、下载、记录 JSON 都可用。
  • r2v 相比 i2v 更能保持整体风格。
  • 多参考图能改善画面一致性，但不等于分镜时间轴。
主要问题
  • i2v 容易穿帮，尤其是人物、影子、复杂异变运动。
  • r2v 对 prompt 的动作执行弱，容易变成静态图推进。
  • 多张不同尺度参考图会被模型融合，而不是按分镜顺序执行。
  • 复杂人物表演、嘴部、经文、衣物、环境同时动时，结果突兀且不流畅。
当前判断：HappyHorse 可作为低成本氛围动图/单动作测试工具，不适合直接承担复杂人物分镜导演。后续应改成短镜头单动作拼接，或转 Seedance / Veo / Runway 做主力视频模型验证。

第一性原理复盘

一致性从哪里来
  • 同尺度、同构图、同风格参考图。
  • 单一主体，低自由度。
  • 避免全景、近景、特写、局部混传给同一条视频。
动画从哪里来
  • 必须明确允许某个区域变化。
  • 一条视频只承载一个核心动作。
  • 不要用“保持不变”把模型完全锁死。
为什么复杂段失败
  • 多参考图不是分镜时间轴。
  • 细粒度动作执行力不足。
  • 5 秒内塞入人物、经卷、衣物、宫灯、墨影，动作目标过载。
下一步原则
  • 每条只测 2-3 秒。
  • 每条只做一个动作：经文游动、墨影扩散、宫灯摇晃、人物嘴动。
  • 用剪辑、音效、字幕制造“分镜”，不要指望单条 r2v 完成导演。
