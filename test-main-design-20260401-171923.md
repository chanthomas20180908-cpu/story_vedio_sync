# Design Doc: Gradio Interface Enhancement

**Project:** story_vedio_sync  
**Branch:** main  
**Date:** 2026-04-01  
**Mode:** Builder (side project/learning)

---

## Problem Statement

The current Gradio web interface (`web/gradio_app.py`) is an MVP that only supports:
- Uploading `.md`/`.txt` story files
- Fixed execution with hardcoded settings (case_kesulu_001 + provider=cloubic)
- No user control over reference images, voice selection, or output format

**What we're building:** Enhance the Gradio UI to support:
1. **Reference image upload** — let users provide their own character/style reference images instead of using hardcoded `assets/ref_images/kesulu_ref.png`
2. **Voice selection** — dropdown to choose between available cloned voices (currently hardcoded to `cosyvoice-v3-flash-manflash01-7cc91b1194ed4a4a982d035734709b8b`)
3. **Skip video generation** — add a checkbox to skip video synthesis (only generate images + audio + subtitles)
4. **Zip output** — already implemented, but ensure it works correctly with the new options

---

## Current State Analysis

### Existing Architecture

**Frontend (`web/gradio_app.py`):**
- Single file upload for story text (`.md`/`.txt`)
- Hardcoded execution: calls `run_case_kesulu_001(upload_file, provider="cloubic")`
- Streaming logs + zip download output
- Concurrency lock to prevent resource contention

**Backend (`web/run_case.py`):**
- `run_case_kesulu_001()` wraps the CLI workflow
- Builds subprocess command: `python -m workflow.story_video_001.cases.case_kesulu_001 --input <file> --provider <provider>`
- Returns `RunResult` with zip path

**Workflow (`workflow/story_video_001/`):**
- `case_kesulu_001.py` — entry point, loads `profile_kesulu_001.PROFILE`
- `activity_script_001.py` — main workflow with 7 steps (spoken → TTS → clean_srt → storyboard → image_prompts → generate_images → compose_video)
- `profile_kesulu_001.py` — configuration dict with:
  - `ref_image`: path to reference image (currently `"assets/ref_images/kesulu_ref.png"`)
  - `cloned_voice_id`: TTS voice ID
  - All other workflow parameters

**CLI Arguments (`activity_script_001.py:build_arg_parser`):**
- `--input` (required): story file path
- `--provider`: "official" or "cloubic"
- `--ref_image`: override profile's ref_image
- `--cloned_voice_id`: override profile's voice
- `--skip_video`: skip video synthesis
- `--skip_images`: skip image generation
- Many other overrides for TTS, video params, etc.

## Design Decisions

### 1. Reference Image Upload

**Approach:** Add a Gradio `File` component for optional reference image upload.

**Implementation:**
- Add `ref_image_upload` parameter to `run_case_kesulu_001()`
- If provided, copy uploaded image to `run_dir/input/ref_image.png`
- Pass `--ref_image <path>` to subprocess command
- If not provided, use profile default (existing behavior)

**Why this works:**
- CLI already supports `--ref_image` override
- No changes needed to workflow logic
- Gradio `File` component handles image upload natively

### 2. Voice Selection

**Approach:** Add a Gradio `Dropdown` with predefined voice options.

**Voice options (from profile analysis):**
- `cosyvoice-v3-flash-manflash01-7cc91b1194ed4a4a982d035734709b8b` (current default, label: "男声 Flash 01")
- Add more voice IDs as needed (requires discovering available voices from TTS provider)

**Implementation:**
- Add `voice_id` parameter to `run_case_kesulu_001()`
- Pass `--cloned_voice_id <voice_id>` to subprocess command
- Default to profile's voice if not specified

**Limitation:** Voice IDs are opaque strings. We'll need to either:
- Hardcode a few known voices with human-readable labels
- OR add a voice discovery mechanism (out of scope for this feature)

**Decision:** Start with 2-3 hardcoded voices, document how to add more.

### 3. Skip Video Generation

**Approach:** Add a Gradio `Checkbox` for "Skip video generation".

**Implementation:**
- Add `skip_video` parameter to `run_case_kesulu_001()`
- If checked, append `--skip_video` to subprocess command
- Workflow already supports this flag

**Why this works:**
- CLI already supports `--skip_video`
- Reduces processing time for users who only want images/audio
- Zip output will contain images + audio + subtitles (no video file)

### 4. Zip Output

**Current state:** Already implemented in `run_case.py:_zip_results()`.

**Verification needed:**
- Ensure zip contains all relevant outputs when `--skip_video` is used
- Current implementation copies `results_dirs` + log — should work correctly

## Edge Cases & Error Handling

1. **Invalid reference image format:**
   - Gradio `file_types=["image"]` handles basic validation
   - Workflow may fail if image format not supported by generation backend
   - Error will appear in logs, user can retry

2. **Reference image too large:**
   - No size validation in UI (out of scope)
   - Backend may fail or resize — depends on generation script
   - Document recommended size (e.g., < 5MB, 1024x1024)

3. **Voice ID not found:**
   - If user somehow provides invalid voice ID, TTS will fail
   - Error appears in logs
   - Mitigation: use dropdown (no free text input)

4. **Skip video + no images:**
   - If `--skip_video` and `--skip_images` both set, only audio/subtitles generated
   - Current UI doesn't expose `--skip_images`, so not a concern
   - Zip will still contain audio + subtitles

5. **No reference image provided:**
   - Use profile default (`assets/ref_images/kesulu_ref.png`)
   - Existing behavior, no change needed

## Testing Strategy

### Manual Testing Checklist

1. **Baseline (no new options):**
   - Upload story file only → should work as before

2. **Reference image upload:**
   - Upload story + custom ref image → verify image used in generation
   - Upload story without ref image → verify default used

3. **Voice selection:**
   - Select different voice → verify audio uses selected voice
   - Use default voice → verify matches current behavior

4. **Skip video:**
   - Check "skip video" → verify zip contains images + audio, no video
   - Uncheck "skip video" → verify video generated

5. **Combined:**
   - Upload story + ref image + custom voice + skip video → verify all options respected

6. **Error cases:**
   - Upload invalid file type → verify error message
   - Upload very large ref image → verify behavior (may fail gracefully)

### Automated Testing

Out of scope for this feature (existing codebase has no tests for Gradio UI).

## NOT in Scope

1. **Voice discovery/listing** — hardcode 2-3 known voices, document how to add more
2. **Reference image validation** — rely on Gradio + backend validation
3. **Multiple reference images** — only support single ref image upload
4. **Profile selection** — still hardcoded to `case_kesulu_001`
5. **Provider selection in UI** — still hardcoded to `cloubic`
6. **Progress bar** — streaming logs are sufficient
7. **Image preview** — zip download is sufficient
8. **Retry mechanism** — user can re-run manually
9. **Input validation beyond file type** — rely on backend errors
